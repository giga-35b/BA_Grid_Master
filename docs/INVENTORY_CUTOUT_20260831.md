# 左下贴图自适应抠图（2026-08-31）

## 本轮实现

- 每张库存贴图独立采样内缩外围，不从棋盘取背景，也不硬编码蓝色或其他主题色。
- 用外围RGB中位数排除离群采样，再取有效采样的颜色范围（含网格线与明暗变化），加少量压缩容差分离背景。外围不具备稳定多数时返回空掩码，沿用无法可靠匹配时的保守处理。
- 复用原有连通区域清理：保留主体与有效分离部件，排除零散噪点、脱离物品的卡片边框。不填满真实间隙，不增加轮廓模型或学习模型。
- 旋转时一起插值RGB和透明掩码，RGB不混入已排除的背景像素，暗色不再被预览的颜色门槛二次删除。
- 预览提高到每格96×96；实际匹配仍为32×32。匹配继续使用双方共有的可靠颜色证据，完整抠图透明度与棋盘物品存在证据分开；没有降低匹配分数/差距门槛，没有扩大角度、缩放或平移搜索。

新增采样只在源贴图准备时执行，不在每个旋转假设内重复。颜色相近且与外部背景相接的细节仍可能丢失，JPEG混色边缘也可能保留少量背景色；不宣称像素级完美分割。

## 棋盘适配边界与用户补充约束

用户补充：基本同色的棋盘可能有花纹；唯一的多色布局族沿对角线重复，**颜色数和周期长度都不固定**。后续应从图像推断重复周期和方向，不能固定为三色、四格或写死颜色，也不能泛化成任意随机多色布局。棋盘颜色与每张库存贴图背景的采样相互独立。

本轮未修改棋盘定位/格子状态算法。用户提供的新活动截图已保存为`app/src/test/resources/inventory-multicolor-event.png`。当前检测能定位约(709,156)-(1337,513)的9×5区域，但把实际45个未开格错误判成23个OPEN_FRAGMENT、22个OPEN_EMPTY；此为明确的旧算法限制，不宣称本包兼容该活动。

新活动的左下物品检查使用人工标出的三个贴图裁区，**不是**自动棋盘/库存完整识别验证。笔身与深色图案已保留，但部分与背景近色的印刷/边缘仍可能被过滤。该图没有已翻开格示例，尚不足以验证其空格、碎片、完成状态的完整判别。
