# 识别调试

## 使用

游戏内点击悬浮按钮完成一次识别，然后返回 App 底栏“结果信息”页的“识别调试”。这里不会重新截取配置页，而是展示刚才那次采集的游戏截图。三个页面独立保留滚动位置；原图/标注与详情展开状态在切换页面时保留。

首页放启动/停止、权限管理跳转、识别来源下拉框、默认折叠的使用说明；设置页放实际权限入口与其余选项。屏幕模式点击启动会请求系统捕获授权，只有捕获建立成功才显示助手。拒绝、取消或启动失败会提示“获取屏幕授权失败”，不启用悬浮窗；系统结束屏幕共享会停止助手和覆盖。最新截图模式不请求/启动屏幕捕获。自行选择模式把主按钮替换为“选择图片”，通过系统选择器读取单张图片并在首页展示带推荐的标注原图，不创建悬浮窗。

- 切换原图 / 标注，点击缩略图进入大图；双击以点击位置为中心放大，再次双击复位；保留双指缩放、拖动。没有独立“放大查看”或“复位”按钮。
- 两种显示状态均有保存按钮，输出完整分辨率 PNG 至相册 `Pictures/BA Grid Master`；不是截取配置页，也不受当前缩放/拖动影响。保存标注与预览共用绘制器。不会覆盖源图。
- 展开所有识别信息，查看采集贴图、卡片 / 形状 / 数量区域、OCR 原文、形状矩阵、剩余数量、45 格状态、物品区域和推荐依据。文字可选中复制。
- 失败时保存本次失败截图和原因，不显示上一次成功结果。捕获前失败则没有截图。
- 仅保留最近一次记录于进程内存；不自动写入磁盘或上传，可手动清空。进程退出后记录丢失。

## 棋盘经验坐标

“设置 → 截图与识别 → 棋盘经验坐标”展示已保存的来源、图片尺寸和两个对角坐标，可通过“移除经验坐标”清空全部记录与待累计样本。移除不删除识别截图、调试记录或其他设置；下次会重新学习。

- 初次建立：在完全未翻开或翻开≤8格时连续识别3次。要求棋盘置信度≥90%、有效格占比≥90%，至少2张物品形状可靠。已勾选仍属于未翻开。
- 同批原始角点两两误差需在数像素内：2400像素宽输入容差4px，1280宽容差2px。稳定后取四个坐标值的均值并持久化；不把校正后的坐标反复拿来训练。
- 每次仍先进行现场棋盘/场景检测。检测不到有效游戏内容时直接拒识，不从旧坐标“生成棋盘”。
- 小偏差校正：比较左、上、右、下四个数值的最大差。阈值为 `min(50 × 输入宽度 / 2400, 0.4 × 单格短边)`，四舍五入到像素。不同尺寸不直接使用固定50px，也不会把整格错位吞掉。
- 超阈值时保留本次检测，不强行校正。只有新的少量翻开高质量画面连续3次稳定，才用新均值替换该来源/尺寸的经验；晚盘即使连续误检也不会污染经验。未识别画面、低质量样本、明显跳变或来源/尺寸切换都会中断当前累计序列。
- 屏幕捕获与相册来源分别记录，输入图片的宽/高必须完全相同才复用。最多保存8组。仅已确立的坐标写入本地，未满3次的样本只在内存中，不保存图片或上传。
- 校正在格子状态和物品匹配之前：重新取样45格、碎片边缘及物品托盘；截图、调试、求解与覆盖共用校正后的坐标。校正后场景校验不通过则撤回，保留原始检测。
- 结果信息中的“注意：经验校正”会显示学习进度、原始/经验角点、像素偏差和是否采用。旧识别记录不会因清除经验而被重新计算。

## 最新截图（次选）

在首页“识别来源”下拉框选择“最新截图”，允许全部照片访问。Android 14+ 的“仅选择部分照片”无法保证读取最新截图，因此不启用这一自动路径；不会绕过权限。该模式不依赖屏幕捕获会话。

每轮使用顺序（包括第一次）：回到实际游戏 → 点击「清屏」 → 0.5 秒后按钮变为可点击的「识别」 → 手动截图并保存 → 点击「识别」。清屏立即丢弃上次覆盖结果，行列刻度、物品标记、推荐框都不会自动恢复；面板不隐藏，而是降至绝对 10% 不透明度持续 3 秒，之后恢复配置值。识别按钮在透明时段内即可使用，提前识别不会取消 3 秒透明计时；长按可重新清屏、重新计时。只清除本应用标注，不会自动发起系统截图。10% 面板仍可能写入截图，必须移出棋盘/物品区。

- 每次重新查询 MediaStore，按入库时间降序、ID 降序读取最新可用图片，不只搜索截图目录。
- 忽略仍在写入/回收站中的图片，以及 `BAGridMasterDebug-` 开头的本应用导出文件，避免导出后读回自己的标注图。
- 清屏时记录时间边界并异步查询当前最大图片 ID；0.5 秒后即可点击识别，若相册服务响应慢则在识别中等待查询，不阻塞按钮切换。识别只接受 ID 更大且拍摄时间不早于边界的新图。没有拍摄时间时保守检查秒级入库时间，同秒新图可能提示重新截图，可等 1 秒再截。旧 ID、未入库的新截图或时间戳表明清屏前拍摄的图直接提示重拍/等待，不重新显示上次结果；没有拍摄时间且延迟入库的图片无法仅凭元数据确定实际截图时间。
- 最新图无法读取或不是有效游戏画面时直接报错，不寻找更旧的成功画面。失败后可截图/等待保存再点「识别」；成功后按钮恢复「清屏」，下一轮必须重新准备。
- 所有悬浮窗档位（包括仅按钮）持续显示“请确认最近截图的是最新待识别画面”。
- 自动处理图片方向及解码内存上限，最多约 800 万像素；调试原图指实际送入识别的图像，大图可能经过等比例缩小。
- 图片必须与当前屏幕方向和宽高比一致（允许 1.5% 舍入误差），按比例映射覆盖坐标，再应用系统栏偏移。比例不符则拒绝覆盖；不会拉伸长截图/竖图。相同比例的裁剪图无法自动判定，仍需用户使用完整截图。
- 模式切换会停止当前助手并清除旧覆盖，需从首页重新启动。撤销照片权限后，下一次识别提示重新授权，不回退旧图。

## 自行选择（备用）

选择该来源后，主按钮显示“选择图片”。系统文档选择器的确认结果提供单张图片的读取授权，不需要“访问所有照片”，也不需要悬浮窗。图片会进行 EXIF 方向归一化和约800万像素的解码上限处理，然后进入与其他来源相同的识别管线。识别成功后，首页按源图坐标叠加棋盘、物品和推荐标注；旋转按钮仅重绘该预览，不修改输入文件、识别坐标或 Activity 屏幕方向。完整报告仍写入“结果信息”。

已经写入旧图片像素的标注无法还原；清屏只移除实时窗口。不要对相册里显示的标注图再次截图，必须回到实际游戏截取新画面。这里用截图前清屏，不使用会使游戏截图变黑的安全窗口标记。

权限实现依据：[Android 共享媒体访问](https://developer.android.com/training/data-storage/shared/media)、[Android 部分照片授权](https://developer.android.com/about/versions/14/changes/partial-photo-video-access)。Android 10+ 保存自建图片无需读取整个相册；Android 8/9 保存时单独请求写入权限。

## 游戏悬浮窗与覆盖层

“设置 → 悬浮窗”提供仅按钮、有限信息、完整信息三档。有限信息仅展示建议坐标（探索格带 `*`）、估计探索置信度与耗时；完整信息另列输入图片的棋盘两顶点、每类物品的形状和剩余/总数、按同类物品左上角排序的清单，如 `[a2 B2横]`。竖放用“纵”，正方形用“方”；无法确定摆放的点亮物品注明“左上?”和已见坐标，不把已见碎片当成物品原点。总数仅在兼容的五种物品组合一致时显示，否则显示 `?`；不把剩余数量当总数。窗口随内容变化，超长完整信息可滚动。按钮30–75dp，旧调试档迁移到完整信息；详细调试仍在结果信息页。

只有圆形按钮的短按触发操作：屏幕捕获模式一键识别，长按清除旧标注；相册模式按「清屏 → 截图 → 识别」两步执行，长按可再次清屏。点击或长按信息区/面板空白处均无操作；普通信息区和面板空白处仍可拖动。拖动超过手势阈值后，即使移回原处再松手也不会识别或清除结果。

拖动松手后，吸附与按钮位置重排会等待当前触摸分发结束再执行。取消触摸只结束手势，不再递归吸附或重建；关闭服务会取消尚未执行的吸附任务。

“游戏覆盖标注”下可独立控制：

- 行列刻度：A–I、1–5 及辅助网格线。
- 左下物品信息（默认关闭）：在三张贴图下侧显示如 `a：3×1，4/4`，标签限制在屏幕范围内。
- 已确定物品位置标注：橙色 `a 点亮`、青色 `c 全开`，a/b/c 固定对应左下清单从左到右。全开物品用一个完整矩形和一个标签，不逐格重复；点亮只标已见格，不把匹配推定的隐藏范围画成事实。空格单独以灰框和“空”表示。
- 未知类型显示“未知”，多个候选显示如 `a/c 点亮`，不强行编号。若 CV 给出缺格或合并导致的非矩形异常区域，则退回已见格轮廓并仅保留一个全开标签，避免大框包含未翻开的格子。调试截图/完整报告仍保留 L/C 分组 ID 与匹配细节，用于排错。

开关实时更新已有覆盖层；不会改变识别计算。推荐框独立保留，覆盖层仍不可触摸，不拦截游戏点击。截图内完整调试标注不受这三个显示开关影响。

## 识别边界

格子状态：`·` 未翻开、`S` 已勾选、`E` 已翻开空格、`L` 彩色碎片、`C` 完成剪影。
`S` 只用于调试展示；求解器、相邻补全和开局查表均把它视为尚未翻开，因此建议可能包含已选格，不应重复点击取消选择。

物品定位使用棋盘内前景像素连通区域，短距离连接跨格缝隙，同格内断开的贴图部分合并。已完成组通过完整矩形尺寸与卡片形状对应；点亮组通过可行尺寸和旋转无关的色相分布列出候选。

类型用左下卡片编号，不假造物品名称；未知 / 多候选明确显示。颜色匹配分只表示色相分布相似，不能说明属于贴图哪一段，也不是校准后的概率。

## 局部贴图匹配与补全

在点亮物品下面可查看：

- **颜色匹配分**：物品类型初筛，和位置匹配分分开显示。
- **局部贴图匹配：已采用 / 未确定**：非正方形先按前景长轴旋转到水平，按形状归一化后切分，再与已见局部格对齐；正方形不依赖旋转贴图，改用格边延伸方向确定摆放。
- **空间纹理分 / 轮廓分 / 明暗纹理分 / 候选差距**：不是命中概率。当前采用阈值为空间纹理分≥0.78、轮廓分≥0.72、不同摆法的分差≥0.045。
- **局部位置**：例如 `B2 → 竖向中段 第2/3格`；条形位置按屏幕从上到下/从左到右编号，二维位置按屏幕方向行列编号，不假设头尾语义。
- **推定占格**：例如 `B1 B2 B3`。仅可靠匹配通过时产生补全建议，隐藏格不会因此被标成“已识别/已翻开物品”。
- **对齐旋转角**：相对左下采集贴图的图像顺时针角度，不是相对游戏原始素材的旋转角。只有占格确定，不表示对称素材的角度一定唯一。
- **形状长轴预对齐**：显示采集贴图预旋转到水平方向的角度，与最终横竖/正反摆放的对齐角分开。
- **未采纳原因与兜底依据**：候选接近、纹理不足、摆法冲突等明确展示；退回真实格边接触和形状约束，绝不把颜色99%当作位置99%。

标注截图中，可靠局部匹配的已见格增加 `2/3` 或 `(行,列)` 小字；完整报告在配置页和悬浮窗调试模式均可查看。未采用的候选仅列在报告中，不画成确定的位置。

完整报告会列出每个点亮物品属于“情况1：可靠匹配”“情况2：延伸完整覆盖”或“情况3：本次尚不能完整补开”。注意信息列出全体门控结果和规划时的数量扣减；任一物品未完成补开条件则本轮不探索。这里的占格/数量调整只用于探索规划，截图中的真实格子状态、左下清单保持原观测。多种完整摆法联合采样，不把候选并集当成一个物品。

相邻贴图粘连、同色同纹理物品、只露出极小部分、透明/发光特效、贴图裁切、形状图标缺失仍可能无法唯一判断。当前空间匹配支持完整矩形占格的物品；无法匹配时不强行声称识别出某一段。

## Finish 完成卡片

右下数量区和中央 Finish 横幅是两个不同区域。报告分别保留数量 OCR、中央 OCR 和完成状态依据。
除 `×0` 外，视觉检测要求中央黄字的比例、六个字形（包括窄 i 和 F 的结构）以及深色横幅同时吻合；不能仅凭卡片变暗判为完成。
数量漏读时追加中央 OCR，读到完整 Finish 可恢复为 0；完成标记与正数库存冲突时保持未知并暂停探索。
完成卡片的灰化形状允许未知，不拿未知形状去参与碎片匹配，也不会再扣一次库存。

## 本机数据集验证

`FullDatasetRegressionTest` 枚举 dataset 下所有 JPG/PNG，按 file_tree.txt 的动作重放棋盘真值；检查格子状态、完成卡和完整摆法，不跳过奖励提示及 others 负样本。
数量 OCR 依赖 Android ML Kit：JVM 回归仅对中央视觉 Finish 做真实像素验证，活动库存使用动作标注推导；不能将此描述成 Android OCR 全量实测。
另外用合成方向证据覆盖2×2四种局部位置、3×3九种局部位置及冲突/缺失证据，并对实际端段图片做缩放/JPEG再编码回归。
