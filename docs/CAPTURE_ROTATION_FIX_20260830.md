# 首次屏幕捕获黑边/偏移修复

## 已确认的故障

手机日志与失败原图对应：竖屏授权时捕获 Surface 为 1080×2400；进入横屏游戏后输出改为
2400×1080，但系统 ContentRecorder 曾使用旧 Surface 尺寸计算 scale=0.45、offset=(0,957)。
因此原图大面积黑屏，只在底部留下游戏的一条窄带。之后同一会话再次旋转也可能恢复正常。
这是捕获尺寸/Surface 更新竞态，不是棋盘 CV 或经验坐标的误判。

## 实现

- Android 14+ 使用 `onCapturedContentResize` 的实际捕获区域尺寸；旧版本保留配置变化回调。
  最大屏幕尺寸仅作初始尺寸，不覆盖系统后来返回的单应用捕获尺寸。
- VirtualDisplay、ImageReader 的创建、调整、取帧、关闭统一在捕获线程串行执行。
- 旋转时先解绑 Surface，间隔 120ms 后调整显示尺寸、创建新 Reader，再间隔 80ms 挂接新 Surface。
  挂接后有 120ms 的缓冲期；期间不交付过渡帧，结束时主动 drain，不要求静态画面产生多个新回调。
  这些间隔是合成器缓冲时间，不是系统已同步的证明，仍需下述帧检查兜底。
- 每次尺寸更新即刻使旧代际失效；快速连续旋转、停止授权后的排队任务不能交付旧帧或重新挂接。
  一份授权只创建一次 VirtualDisplay；恢复仅复用该实例，不二次消费授权。
- 对全黑、或大面积黑色且内容仅在边缘窄带的帧拒绝识别，并按当前尺寸最多重新同步一次。
  恢复后仍失败则给出捕获异常提示，不裁切/拉伸残缺帧，不进入 CV 或经验坐标学习。
- 截图请求有独立身份，旧请求的成功/失败不能影响下一次请求。超时作为可显示的捕获错误，
  不再被当成普通协程取消而漏掉提示。主动取消仍正常传播。
- 被拒绝的原图保留在结果信息中，仍可查看和保存；添加尺寸、代际、重绑、拒绝和交付日志，
  标签为 `BAGridCapture`。相册读取、CV 匹配及推荐算法未改变。

## 验证

运行 `:app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest`。

- 167 项 JVM 测试，0 失败、0 错误、0 跳过；新增 17 项捕获相关测试。
- 包含精确复现 2400×1080 / 底部 y=957 / 内容宽 1080 的合成异常帧。
- 45 张数据集图片全部通过捕获完整性检查；原有 CV/校准全数据集回归继续通过。
  非游戏负样本仍交给 CV 正常拒绝，不将帧完整性检查冒充游戏识别。
- Lint 0 错误，2 项原有警告；应用和 instrumentation APK 均构建成功。
- 未安装或操作手机。上述自动测试不能替代厂商 MediaProjection 的真机验证。

建议真机验证：竖屏打开首页并授权后，第一次进入横屏游戏识别；连续切换横竖屏后再识别；
切换过程中点击识别；主动结束共享。应分别得到完整原图、当前尺寸的新帧、等待/明确错误提示、
以及悬浮助手自动停用。若仍异常，保留失败原图并检查 `BAGridCapture` 和系统 ContentRecorder 日志。

API 依据：[Android MediaProjection 文档](https://developer.android.com/media/grow/media-projection)。
