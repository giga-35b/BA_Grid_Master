# BA Grid Master

《蔚蓝档案》挖格子小游戏的辅助App，**基于纯机器视觉方案实现，不会读取游戏内存或自动点击游戏屏幕**。

它会**从游戏截图中识别棋盘、物品形状和剩余数量，并标出建议翻开的格子**。

> 注：识别和计算结果仅供参考。请先核对棋盘标注，确认无误后再手动翻开格子。

## 功能

- **三种图片来源输入方式**：
  - **模式① - 屏幕捕获**：直接捕获游戏画面；
  - **模式② - 最新截图**：自动读取相册中的最新截图；
  - **模式③ - 自行选择**：从相册手动选择一张图片。

- **计算参数选择**：探索算法可选“有限前瞻”或“贪婪”；可调整截图等待时间、经验坐标校正和黑边检测。
- **多种结果输出形式**：
  - **悬浮窗（仅限模式①/②）**：可调整透明度、按钮大小、信息量（仅按钮/简要/完整）。模式②（最新截图）还提供“临时隐藏”按钮，方便截取没有悬浮窗的游戏画面。
  - **游戏内覆盖（仅限模式①/②）**：直接在棋盘上绘制推荐格、行列坐标和已确定的物品位置，不拦截游戏点击；颜色、线宽和显示内容可在设置中调整。
  - **App首页显示（仅限模式③）**：在App首页显示绘制了推荐格的结果图，类似模式①/②的游戏内覆盖。
  - **App 内调试信息**：可详细查看原图/标注图、格子状态和识别依据等；大图支持放大、保存等功能。


## 使用方法

[介绍视频（B站）](https://space.bilibili.com/15097920)

请使用包含完整棋盘和左下三张物品卡的横屏原图，不要使用裁剪图、长截图或本应用导出的标注图再次识别。

### 1. 屏幕捕获（推荐）

1. 在“权限管理”中允许悬浮窗显示，首页选择“屏幕捕获”。
2. 点击“启动悬浮助手”，同意系统的屏幕捕获授权。
3. 进入游戏，把悬浮窗移出棋盘和物品卡区域，点击悬浮按钮开始识别。
4. 核对覆盖标注后，按建议在游戏中手动翻格。

### 2. 最新截图（次选）

1. 允许悬浮窗显示和访问全部照片，首页选择“最新截图”并启动助手。
2. 在游戏中点击“清屏”；也可以点击随后出现的“临时隐藏”。
3. 手动截图，保存一张新的完整游戏截图。
4. 完成截图后点击“识别”，再核对游戏内覆盖结果。

应用只读取“清屏”之后保存的新截图，不会反复使用旧图片。

### 3. 自行选择（备用）

1. 首页选择“自行选择”，点击“选择图片”。
2. 在系统图片选择器中选中一张完整游戏截图。
3. 等待识别完成，在首页查看合成后的标注图；点击图片可放大、旋转或保存。
4. 如需查看详细判断过程，进入底部的“结果信息”。

此模式不需要悬浮窗权限，也不需要授予整个相册的访问权限。

## 结果说明

- 普通推荐格用于补全已经点亮的物品；带 `*` 的推荐格表示额外探索。
- “有限前瞻”会同时考虑当前选择和一次落空后的后续收益；“贪婪”只选择当前命中率最高的格子，计算更快。
- **遮挡、截图缩放、画质过低或新的活动主题都可能造成误判。**证据不足时，应用可能只建议补开物品、不额外探索，或提示重新识别。**如有误判，请在App“结果信息”页保存标注图、复制完整调试信息，向作者反馈。**
- “结果信息”会保留最近一次识别的原图、完整标注和诊断内容，便于核对或反馈问题。

更完整的权限说明、设置解释和故障排查请参阅[用户手册](docs/USER_MANUAL.md)（普通用户不需要看）。

## 算法与开发

应用在本机完成棋盘定位、格子分类、物品卡与数量识别，并结合边缘纹理、物品形状约束、局部贴图和完成剪影生成建议。算法概览见[策略说明](docs/STRATEGY.md)，工程结构见[架构说明](docs/ARCHITECTURE.md)，诊断字段见[调试说明](docs/DEBUGGING.md)。

构建环境和签名边界见[构建说明](docs/BUILDING.md)。配置 JDK 与 Android SDK 后，可在仓库根目录执行：

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug --no-daemon
```

应用的截图采集和识别在本机执行，当前 Manifest 未声明网络权限。主动分享截图或诊断信息前，请检查其中是否包含账号、通知或其他个人信息。
