# 手机屏幕捕获与电脑端录制短测

历史测试记录。公开仓库仅保留本说明和静态拼图，原视频与设备日志不随源码发布。重跑前请按 `docs/BUILDING.md` 安装 scrcpy 并配置 SDK。

- 工具：官方 scrcpy 4.1 Windows 便携版；无线 ADB；小米2410DPN6CC / Android 16。
- 下载ZIP的SHA256与官方发布元数据一致：`5B12172B3264B2889F4583EE64752CE832E29BC8B1089DCA81093459697165DB`。
- 未安装手机APK，未修改 Grid Master、系统权限或应用设置。scrcpy使用临时服务端；录制自动结束。
- 视频 `screen.mp4`：30.105 秒，H.264，1920×864，约 29.93 fps，无音轨，3335165 字节。
- 六张抽帧均可见正常游戏画面，前半段可见助手悬浮窗与覆盖标注；全片黑帧检测未报告持续0.2秒以上、98%画面为黑色的区间。
- 手机应用在 scrcpy 录制期间交付 LIVE 帧并返回识别结果：识别 654 ms、推荐 32 ms、总耗时 796 ms。这证明至少该次识别与电脑录制同时成功；不是长时间稳定性保证。
- 随后应用释放捕获流；录制后 `dumpsys media_projection` 为空，后半段悬浮窗消失。用户确认是主动停止助手，并非本次 scrcpy 录制导致的异常中断。短测已证明两者可同时工作，但尚未做长时间稳定性测试。
- 小米系统拒绝scrcpy写`show_touches`及注入电脑输入。触摸设置录前/录后均为0，没有提升权限。可在手机开发者选项中自行开启触摸显示。
- 后续脚本`tools/Record-PhoneScreen.ps1`改用`--no-control`，不自动设置触摸点；手机直接操作、电脑只读投屏录制。该脚本已进行语法检查，尚未再次录制。

在项目目录运行：`./tools/Record-PhoneScreen.ps1 -Seconds 300`。视频保存到独立时间戳目录，不覆盖旧文件。请勿同时启用手机自带录屏。
